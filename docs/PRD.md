## **2. 모델 아키텍처**

### **2-1. Multi-Modal Fusion Model**
기상 시계열 데이터와 천리안 위성 이미지를 결합(Late Fusion)하여 제주 전체 발전량을 예측하는 딥러닝 네트워크.

```
                  [수치 기상 데이터 (24, 9)]           [위성 크롭 이미지 (3, 112, 112)]
                              │                                      │
                              ▼                                      ▼
                        LSTM Branch 1                          ResNet18 Backbone
                        (Hidden: 128)                                │
                              │                                      ▼
                        LSTM Branch 2                         Linear layer (512->64)
                        (Hidden: 64)                                 │
                              │                                      │
                              ▼                                      ▼
                      [기상 특징 벡터 (64)] ─────────────── [이미지 특징 벡터 (64)]
                                             │
                                             ▼ (Concatenate)
                                     [Fusion FC (128)]
                                             │
                                             ▼
                                  [최종 예측 레이어 (2)]
                                   - 태양광 발전량 (MW)
                                   - 풍력 발전량 (MW)
```

*   **수치형 LSTM 브랜치**: 24시간×9개 피처를 입력받아 두 층의 LSTM(`hidden_size=128 → 64`, `dropout=0.2`)을 거쳐 시간적 종속성을 파악합니다.
*   **이미지 CNN 브랜치**: 제주도 좌표 영역(`left:237, top:301, right:275, bottom:323`)만 크롭한 112x112 위성 이미지를 ResNet18 백본 및 Linear 레이어(`512 → 64`)를 거쳐 고수준 공간 특징으로 추출합니다.
*   **손실 함수**: L1 Loss(MAE)와 L2 Loss(MSE)를 혼합한 `Hybrid Loss (0.7*MAE + 0.3*MSE)`를 사용하여 급변점 오차와 평균 오차를 동시에 최소화합니다.

## **3. 설명 가능한 AI 및 에이전트 시스템 (KG-RAG)**

### **3-1. 지식 그래프 스키마 (NetworkX 기반)**
단순 텍스트 타임스탬프 검색 한계를 해결하기 위해, 노드 네이밍 규칙을 표준화하고 물리적 제약을 명시적 노드로 구성했습니다.

*   **노드 명세**:
    *   `WeatherSnapshot` (노드 ID: `timestamp` 문자열 예: `"2025-12-09 14:00:00"`): 해당 시점의 기상 수치 관측치.
    *   `WeatherEvent` (노드 ID: `ev_{event_type}_{ts}`): 특이 기상 이벤트 (예: `high_wind` - 풍속 18m/s 이상 경보).
    *   `PhysicsRule` (노드 ID: `rule_...`): 설비 및 자연 물리 제약 조건.
        *   `rule_night_solar` (일조량 ≤ 0.01인 야간 태양광 출력 0 강제)
        *   `rule_cutin_wind` (풍속 < 3.0m/s 시 풍력 출력 0 강제)
        *   `rule_cutout_wind` (풍속 > 25.0m/s 시 설비보호용 풍력 차단)
*   **관계(Edge) 명세**:
    *   `APPLIES` (`WeatherSnapshot` → `PhysicsRule`): 기상 상태에 해당 물리 법칙이 바인딩됨.
    *   `TRIGGERS` (`WeatherSnapshot` → `WeatherEvent`): 기상 임계치 도달 시 기상 경보가 발생함.

### **3-2. RAG-to-KG 하이브리드 날씨 매핑 & 검색**
예보 데이터가 존재하지 않는 먼 미래 또는 기상청 API 장애 상황에서 가상 날씨를 단순 무작위 난수로 생성하지 않고, RAG를 이용해 실제 기상 데이터를 재구성합니다.

```
1. 예보 시점 입력 (예: 2027-07-15 19:00:00) 
   ──> KMA API 단기예보 범위 밖 감지
   
2. 타임스탬프 분석 (7월, 19시) 
   ──> FAISS 메타데이터 검색 및 과거 동일 계절/시간대 행 필터링
   
3. 기상 윈도우 역복원 
   ──> 매칭된 과거 인덱스 추출 ──> FAISS Index에서 216차원 기상 벡터 reconstruct 
   ──> feature_scaler.inverse_transform 역변환 ──> (24, 9) 원본 스케일 날씨 윈도우 복원
   
4. RAG-to-KG 하이브리드 체인 
   ──> 복원된 과거 시점의 타임스탬프 노드로 지식 그래프(KG) 탐색 
   ──> 기상 경보(WeatherEvent) 및 물리 법칙(PhysicsRule) 데이터 동시 수집 
   ──> 챗봇 및 설명 모델(Explainer) 입력으로 전달
```

### **3-3. 자율 재예측 및 불확실성 앙상블 (Self-Refinement)**
모델 예측 시 기상 경보가 2개 이상 활성화되거나, RAG 유사 사례 검색 시의 벡터 거리가 기준치(L2 distance > 10.0)를 초과하여 **예측 신뢰도가 'Low'로 저하될 경우** 작동합니다.
1.  **3시간 전 슬라이딩**: 현재 입력 윈도우를 시간 축 기준 3단계 뒤로 밀고 앞 영역을 보정하여 재예측을 수행합니다.
2.  **앙상블 예측**: 기존 예측치와 3시간 전 기준 예측치를 결합(평균)하여 최종 발전량으로 수정 갱신합니다.
3.  **불확실성 구간 도출**: 두 예측치의 차이를 통해 신뢰 구간(하한 `Range Low` ~ 상한 `Range High`)을 도출해 에이전트 리포트에 포함합니다.
