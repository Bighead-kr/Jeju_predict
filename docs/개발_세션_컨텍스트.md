## 2. 오늘(2026-06-15) 개발 순서

### 규칙

- **백엔드** 항목은 순서대로 구현 (UI 참고자료 불필요)
- **프론트엔드(UI)** 항목 차례가 되면 → **사용자에게 추가 참고 자료 요청 후 구현**
- 각 항목 완료 시 TodoWrite로 상태 업데이트

---

### Phase A — 백엔드 (UI 불필요, 순차 구현)

#### A-1. [P0] 기상청 단기예보 API 연동
- **대상 파일**: `app/agent.py` `_build_window()` → 랜덤 시뮬레이션 제거
- **목표**: 실제 기상 데이터로 발전량 예측 입력 교체
- **참고**: 기상청 단기예보 조회서비스 API (공공데이터포털)
- **주의**: API 키는 `.env`의 `KMA_API_KEY`로 관리

#### A-2. [P0] tool_validate 자기검증 도구 분리
- **대상 파일**: `app/agent.py` 물리 규칙 → `app/services/validator.py` + `agentic_chat.py` TOOLS 등록
- **검증 항목**: 야간 태양광=0, cut-in(3m/s)/cut-out(25m/s) 풍속, z-score 이상치, 용량 상한 초과
- **목표**: tool_validate가 불합격 사유를 구조화해 반환 → 루프가 재시도

#### A-3. [P1] services/event_store.py 신규
- 트리거·경보 발동 시 이벤트를 `data/events.json`에 append
- 구조: `{timestamp, type, reason, action, prediction_after}`
- `/events` GET API 엔드포인트 추가 (main.py)

#### A-4. [P1] services/monitor.py 신규
- APScheduler로 06:00 / 12:00 / 18:00 정시 예측 실행
- 트리거 감지 시 event_store에 기록 + notifier 호출
- FastAPI lifespan 이벤트로 백그라운드 스케줄러 등록

#### A-5. [P1] services/notifier.py 신규
- 경보 발동 시 이메일 발송 (smtplib 또는 SendGrid)
- 수신인은 `.env`의 `ALERT_EMAIL`로 설정
- tool_notify로 agentic_chat.py TOOLS에 등록

#### A-6. [P2] services/memory.py 신규
- 과거 예측 결과·경보 이력을 FAISS 벡터로 저장 (rag_service.py 패턴 재활용)
- AgenticChatService의 장기 메모리로 연결 ("지난 태풍 때" 질문 대응)

#### A-7. [P2] services/report_gen.py 신규
- 일간 24H 예측 요약 + 경보 이력 → HTML/JSON 생성
- tool_make_report로 TOOLS 등록
- `/report/{date}` GET API 엔드포인트 추가

### Phase B — 프론트엔드 (UI 참고 자료 요청 후 구현)

> **규칙**: B 항목 차례가 되면 "B-N 구현 시작. [항목명] 구현에 참고할 디자인 자료나 스크린샷을 공유해주세요." 라고 요청

#### B-1. [P1] 글로벌 에이전트 상태바 + 🔔 알림 카운터
- 모든 탭 상단 고정 (32px), 정상🟢/트리거🟡/경보🔴 색상 전환
- 클릭 시 최근 경보 3건 드롭다운, nav 우측 🔔(n) 미확인 카운터

#### B-2. [P1] 레이아웃 재구성
- 본문 + 우측 에이전트 레일 2컬럼 셸
- 기본 랜딩: 지도 → 관제 홈(현 운영자 대시보드)으로 재루팅
- 탭 재명명: 운영자→관제 홈, 지도→권역 지도, 캘린더→예보 달력
- 레일: 🟢상태 / 📋경보 이력 / 🧠추론 로그 / 🕐예약 / 💬챗봇(통합)

#### B-3. [P1] 권역 지도 탭 개선
- 지도 위 좌상단 플로팅 상태 오버레이 (에이전트 상태 + 전역 발전량)
- 트리거 시 해당 권역 마커 → pulse-marker-red 자동 전환
- 우측 패널 → 예측 근거 카드 (수치+신뢰도뱃지+주요변수Top2+유사사례)
- regionMockData 제거 → /predict API 기반 실시간 데이터

#### B-4. [P1] 관제 홈(운영자) 탭 개선
- KPI 5번째 카드: 에이전트 상태 (정상/경보, 마지막 갱신, 다음 스케줄)
- 24H 차트: Math.random 제거 + range_low/high 반투명 불확실성 밴드
- 경보 이력 패널: event_store 데이터 연결 (현재 HTML 골격만 있음)
- 기상 인디케이터 하드코딩 제거 → current_window 실측값 연결
- 예측 설명 패널: '설명 생성' 버튼 → 관제 실행 시 자동 갱신

#### B-5. [P2] 예보 달력 탭 개선
- 달력 셀 day%3 더미 → /daily_data API 기반 실수치(MW)
- 경보 이력 있는 날짜 → ⚠️ 뱃지
- 월간 누적 진행 바 (목표 대비 달성률)
- 오른쪽 패널: 과거 날짜 선택 시 실측 vs 예측 오차 비교

#### B-6. [P2] 탭 간 컨텍스트 연동
- 관제 홈 경보 클릭 → 권역 지도 해당 권역 자동 선택
- 예보 달력 날짜 클릭 → 관제 홈 시점 데이터 동기화

## 3. 핵심 아키텍처 파일 맵

```
app/
├── agent.py              # LSTM 예측 파이프라인, run_pipeline_with_refinement
├── main.py               # FastAPI 라우터
├── config.py             # 경로 상수
├── models/
│   └── lstm_model.py     # MultiModalFusionModel (LSTM+CNN)
├── services/
│   ├── agentic_chat.py   # Claude Function Calling 멀티스텝 에이전트 (핵심)
│   ├── rag_service.py    # FAISS 유사 사례 검색
│   ├── kg_service.py     # NetworkX 지식그래프
│   ├── explainer.py      # 예측 설명 생성
│   ├── event_store.py    # [미구현] 경보 이벤트 영속화
│   ├── monitor.py        # [미구현] APScheduler 능동 모니터링
│   ├── notifier.py       # [미구현] 이메일 알림
│   ├── memory.py         # [미구현] FAISS 장기 메모리
│   └── report_gen.py     # [미구현] 일간 리포트 생성
└── templates/
    └── index.html        # 프론트엔드 SPA (3탭 구조)

docs/
├── 에이전트_고도화_방안.md    # 에이전트 아키텍처 고도화 로드맵
├── 에이전트_UX기능_분석.md   # 타겟 사용자 분석 + UI 개선 방향
└── 개발_세션_컨텍스트.md     # 이 파일 — 세션 간 개발 맥락 공유
```
