# 제주 신재생에너지 발전량 예측 — "시스템"에서 "에이전트"로

> 작성일: 2026-06-14
> 목적: 현재 구현이 왜 *에이전트*보다 *예측 시스템*에 가까운지 진단하고, 진정한 에이전트로 전환하기 위한 구체적 추가·변경 사항을 정리한다.

---

## 1. 현재 구조 요약 (As-Is)

| 구성요소 | 파일 | 역할 |
| --- | --- | --- |
| 예측 파이프라인 | [app/agent.py](../app/agent.py) | LSTM+CNN 예측 → 물리규칙 보정 → 트리거 판단 → RAG/KG 조회 → 리포트 |
| 자율 재예측 | `run_pipeline_with_refinement` | confidence=Low일 때 윈도우 3시간 시프트 후 **1회** 재예측 |
| 대화형 Q&A | [app/services/agentic_chat.py](../app/services/agentic_chat.py) | intent 분류(Claude) → 정적 분기(Step A~E) → 도구 호출 → 답변 생성(Claude) |
| 도구들 | rag_service / kg_service / explainer | 유사사례(FAISS), 지식그래프(NetworkX), 설명 생성 |

핵심 흐름:
```
사용자 질문 → Claude(의도분류) → if/elif 분기로 도구 선택 → 도구 실행 → Claude(문장 생성)
```

---

## 2. 왜 아직 "에이전트"가 아닌가 (진단)

현재 시스템은 **잘 만들어진 파이프라인 + LLM 래퍼**다. 에이전트의 핵심 속성 대부분이 빠져 있다.

| 에이전트 속성 | 현재 상태 | 근거 |
| --- | --- | --- |
| **자율적 도구 선택** | ❌ 정적 매핑 | `chat()`의 Step A~E는 intent→if문 고정 분기. LLM은 도구를 *고르지* 않고 분류·문장 생성만 담당 |
| **동적 추론 루프(ReAct)** | ❌ 단발성 | 한 번 분기 타고 끝. 관찰→재계획 루프 없음 |
| **LLM Function Calling** | ❌ 미사용 | Anthropic `tools` 파라미터 미사용. 도구 호출은 전부 파이썬 코드 |
| **목표 지향성** | ❌ 없음 | "발전량 알려줘" 단답만. "내일 운영계획 세워줘" 같은 상위 목표 분해 불가 |
| **자기검증/자기수정** | △ 휴리스틱 | confidence=Low 시 고정된 1회 시프트 재예측뿐. 결과를 *평가*해 반복하지 않음 |
| **메모리** | △ 빈약 | 대화 10턴 텍스트만. 장기 메모리·작업 상태·사용자 선호 없음 |
| **능동성(Proactive)** | ❌ 없음 | 사용자가 물어야만 동작. 이상 징후 자동 감지·경보 없음 |
| **행동(Action)** | ❌ 없음 | 읽기 전용 Q&A. 알림 발송·운영권고·재학습 트리거 등 외부 액션 없음 |

> 요약: **"인지(예측·설명)"는 있으나 "판단의 자율성·반복·행동"이 없다.** 그래서 시스템에 가깝다.

## 3. 목표 구조 (To-Be)

```
사용자 목표 → [Planner] 작업 분해
            → [Agent Loop] 관찰 → 추론 → 도구선택(LLM tool-use) → 실행 → 평가
                                       ↑__________ 종료조건 미충족 시 반복 __________|
            → [Action] 리포트/경보/운영권고 → [Memory] 결과·선호 영속화
```

## 4. 구체적 추가·변경 사항 (우선순위순)

### 🥇 P1. LLM Function Calling 기반 동적 도구 선택 (가장 중요)
- **변경**: `agentic_chat.chat()`의 정적 Step A~E 분기를 제거하고, 기존 도구들(`tool_predict`, `tool_lookup`, `tool_rag`, `tool_kg`, `tool_explain`, `tool_compare`)을 Anthropic **`tools` 스키마**로 등록.
- Claude가 질문을 보고 **어떤 도구를, 어떤 순서로, 몇 번** 호출할지 스스로 결정 → `tool_use` 블록 반환 → 실행 → `tool_result` 회신 → 루프.
- **효과**: "정적 if문"이 "자율 판단"으로 바뀜. 이것만으로 시스템→에이전트 전환의 70%.
- 기존 도구 함수는 그대로 재사용 가능(시그니처만 정리).

### 🥈 P2. Plan–Act–Observe–Reflect 루프
- 최대 N스텝(예: 6) 반복하며, 매 스텝 결과를 관찰하고 종료 조건(충분한 답/목표 달성)을 LLM이 판단.
- 기존 `run_pipeline_with_refinement`의 "1회 고정 재예측"을 **평가 기반 반복**으로 일반화:
  - 예측 → 자기검증(아래 P3) → 불합격 시 입력/가정 바꿔 재예측 → 합격 또는 한계 도달까지.
- `tool_trace`(이미 존재)를 추론 로그로 확장해 관측가능성 확보.

### 🥉 P3. 자기검증(Self-Verification) 도구
- 새 도구 `tool_validate(report, timestamp)`:
  - 물리 타당성(야간 태양광=0, cut-in/out 풍속), 과거 동월·동시간 분포 대비 이상치(z-score), 용량 상한 초과 여부 검사.
  - 불합격 사유를 구조화해 반환 → 루프가 이를 보고 재시도.
- 현재 `agent.py`의 하드코딩 물리규칙을 이 도구로 이전·확장.

### P4. 메모리 계층화
- **단기**: 현재 `history`(유지).
- **장기**: 사용자 질의·선호·과거 예측 결과를 벡터 저장(FAISS 재활용) → 유사 과거 대화 회수.
- **작업 상태**: 진행 중 목표/하위작업을 JSON으로 영속화(멀티턴·세션 간 연속성).

### P5. 능동적 모니터링 에이전트 (Proactive)
- 백그라운드 스케줄러(예: APScheduler)로 신규 기상 입력 감지 → 자동 재예측.
- 트리거(전운량 급변·고풍속·기압 급변, 이미 `agent.py`에 로직 존재) 발동 시 **사용자가 묻지 않아도** 경보 생성.
- 이로써 "응답형"에서 "감시·선제형"으로 전환.

### P6. 행동(Action) 도구 확장
- `tool_make_report`(일/주간 운영 리포트 생성·저장), `tool_notify`(임계 초과 알림), `tool_recommend_ops`(발전 계획·수요 대응 권고), `tool_queue_retrain`(드리프트 감지 시 재학습 큐 등록).
- 에이전트가 "분석"을 넘어 "조치"를 하게 됨.

### P7. 멀티 에이전트 오케스트레이션 (확장)
- 역할 분리: **예측 에이전트 / 검증 에이전트 / 설명 에이전트 / 운영권고 에이전트**.
- 상위 오케스트레이터가 목표를 배분·취합. (P1~P3 안정화 후 도입 권장)

### P8. 불확실성 정량화 고도화
- 현재 2회 앙상블 → MC Dropout, 분위수 회귀(quantile)로 예측구간 산출 → 검증·권고의 근거 강화.

## 5. As-Is vs To-Be 비교 한눈에

| 항목 | As-Is (시스템) | To-Be (에이전트) |
| --- | --- | --- |
| 도구 선택 | 정적 if/elif | LLM이 동적 결정 (function calling) |
| 실행 방식 | 1-pass 파이프라인 | Plan→Act→Observe→Reflect 루프 |
| 재예측 | confidence Low 시 1회 시프트 | 자기검증 불합격 시 반복 개선 |
| 메모리 | 대화 10턴 | 단기+장기+작업상태 |
| 동작 트리거 | 사용자 질문 only | 질문 + 능동 모니터링 |
| 산출물 | 텍스트 답변 | 답변 + 리포트/경보/운영권고 |
| LLM 역할 | NLU/NLG 래퍼 | 추론·계획·도구 호출 주체 |

---

## 6. 단계별 로드맵

- **Phase 1 (1~2주)**: P1 도구 function-calling 전환 + P2 추론 루프. → 체감상 즉시 "에이전트화".
- **Phase 2 (2~3주)**: P3 자기검증 도구 + P4 메모리. → 신뢰성·연속성 확보.
- **Phase 3 (3~4주)**: P5 능동 모니터링 + P6 액션 도구. → 선제적·실행형 에이전트.
- **Phase 4 (확장)**: P7 멀티에이전트 + P8 불확실성 고도화.

---

## 7. 가장 적은 노력으로 가장 큰 전환 (Quick Win)

> **P1만 먼저 적용하라.** `chat()`의 정적 분기를 Anthropic tool-use 루프로 바꾸는 것만으로 기존 6개 도구가 그대로 "에이전트가 자율적으로 부리는 도구"가 된다. 코드 변경 범위는 `agentic_chat.py` 한 파일에 집중되고, 도구 구현은 재사용된다.
